## Cartão (preenchido pelo CTO)

### Objetivo

Uma migração cria do zero, num Postgres vazio, todas as tabelas do MVP (spec 10), com RLS ligado sem políticas e o índice único `(account_id, identity_key)`. O app tem um cliente de banco só de servidor.

### Contexto mínimo

- Spec seções 6 (pooler, `prepare: false`, migração pela 5432), 10 (tabelas e colunas do MVP, restrições), 14 (segredos). ADR-0021 (todas as decisões), ADR-0018 item 5 (datas civis), ADR-0019 item 3 (variáveis por etapa).
- **Instale** `drizzle-orm`, `postgres` (dependencies) e `drizzle-kit` (devDependencies), versões estáveis atuais (`pnpm view`). Nenhuma outra dependência. Se o pnpm 12 pedir aprovação de build script, relate qual.
- Confira a API do Drizzle na documentação oficial ou nos tipos instalados em `node_modules` (`pgTable`, `bigint({ mode: 'bigint' })`, `date({ mode: 'string' })`, `uniqueIndex`, `pgEnum`, `drizzle.config.ts`). Não invente API; marque **[VERIFICAR]** no relatório o que não conseguiu conferir.
- Tabelas: `users`, `institutions`, `connections`, `accounts`, `transactions`, `categories`, `merchant_rules`, `imports`, `import_items`, `holdings`, `sync_logs`, com as colunas da spec 10. Enums de texto como `pgEnum` ou `text` com `CHECK` (decida e registre). `external_item_id` é segredo: coluna `text`, nunca em log (a criptografia é do E3; registre como pendência).
- Restrições mínimas: FKs com `ON DELETE RESTRICT`; `transactions.identity_key NOT NULL`; `uniqueIndex` em `(account_id, identity_key)`; `amount`, `balance`, `available_balance`, `reconciliation_diff`, `holdings.balance` e `import_items.parsed_amount` em `bigint`; `transactions.deleted_at` nullable; índices nas FKs usadas em consultas (`transactions(account_id, date)`, `transactions(user_id, date)`).
- RLS: a migração, depois das tabelas, tem `ALTER TABLE ... ENABLE ROW LEVEL SECURITY;` e `ALTER TABLE ... FORCE ROW LEVEL SECURITY;` para **cada** tabela. Se o `drizzle-kit generate` não gerar isso, acrescente uma migração SQL própria (`drizzle-kit generate --custom`) e explique.
- `DATABASE_URL_MIGRATIONS` passa a ser **obrigatória só para o script de migração** (não para o app): `drizzle.config.ts` lê a variável e falha com a mensagem que nomeia a variável, sem valor.
- Postgres para verificar: o Docker existe nesta máquina, mas o daemon pode não estar ligado. Há binários do Postgres 16 em `/usr/lib/postgresql/16/bin`: se o Docker falhar, suba um cluster temporário com `initdb` + `pg_ctl` numa pasta temporária fora do repositório, porta livre (ex.: 55432), e desligue no fim. Registre qual usou.

### Casos de teste

`tests/lib/database/schema.test.ts` (lê os `.sql` de `drizzle/`):

| Caso | Esperado |
|---|---|
| Cada `CREATE TABLE` das 11 tabelas | existe |
| Cada tabela criada | tem `ENABLE ROW LEVEL SECURITY` e `FORCE ROW LEVEL SECURITY` |
| Nenhuma migração | contém `CREATE POLICY` |
| `transactions` | `identity_key` `NOT NULL`; índice único em `(account_id, identity_key)` |
| colunas de dinheiro listadas acima | tipo `bigint`; nenhuma `real`, `double precision`, `numeric` ou `money` em todo o schema |
| `transactions.date`, `imports.period_start/end` | tipo `date` |
| toda tabela de dados (todas menos `institutions`) | tem `user_id` (ou, em `import_items`, a FK para `imports`) |

`tests/integration/migration.test.ts` (com `TEST_DATABASE_URL` de um banco vazio):

| Caso | Esperado |
|---|---|
| aplicar as migrações num banco vazio | sem erro; as 11 tabelas existem |
| `pg_class.relrowsecurity` e `relforcerowsecurity` | `true` em todas |
| inserir duas transações com mesmo `(account_id, identity_key)` | a segunda falha com violação de unicidade (`23505`) |
| aplicar de novo | não faz nada e não falha |

- **O que foi feito:** schema das 11 tabelas da spec 10; migração 0000 gerada pelo `drizzle-kit generate`; migração 0001 criada com `generate --custom` (o drizzle-kit não gera `ENABLE/FORCE ROW LEVEL SECURITY` sem `.enableRLS()` e não gera FORCE) com ENABLE e FORCE para as 11 tabelas, sem políticas; cliente `db()` preguiçoso com `prepare: false` e `env().DATABASE_URL`; nenhum arquivo de `app/` o importa.
- **Decisões tomadas:**
  - Enums como `text` + `CHECK` (evolui sem `ALTER TYPE`). `type` de `institutions`/`transactions`, `status` de `connections`/`accounts` e `source` de `imports` ficam livres, pois a spec não lista valores.
  - `pnpm-workspace.yaml` com `allowBuilds: { esbuild: false }`: o pnpm 12 recusava o `install` (ERR_PNPM_IGNORED_BUILDS) por scripts de build do esbuild (dependência do drizzle-kit). Os scripts NÃO são executados; o drizzle-kit funciona sem eles. Precisa de ciência do CTO.
  - `drizzle.config.ts` exige `DATABASE_URL_MIGRATIONS` já na carga, então `db:generate` também precisa dela (pode ser uma URL fictícia, pois não conecta).
  - `connection_id` anulável em `accounts` e `sync_logs` (conta Caju não tem conexão Pluggy); obrigatório em `holdings`. `confidence` é `integer` (escala não definida na spec). `count` de linhas de `imports` é `integer`.
  - `merchant_rules.category_id` obrigatório; `transactions.description` obrigatório; `holdings.balance` NOT NULL.
  - Sem `ON UPDATE` automático: `updated_at` é responsabilidade do repositório (T2.6).
  - `transfer_pair_id` é `uuid` sem FK (par entre duas transações; a spec não define a regra).
- **Riscos e dúvidas:**
  - `FORCE ROW LEVEL SECURITY` sem políticas nega tudo inclusive ao dono da tabela, a menos que o papel tenha `BYPASSRLS` ou seja superusuário. No Supabase o papel `postgres` tem `BYPASSRLS`; o papel usado pelo app e pelas migrações precisa ser conferido na T2.8. No cluster local o superusuário ignora RLS, então este teste não prova o bloqueio (é da T2.8).
  - Teste estático usa regex sobre o SQL do drizzle-kit 0.31; mudança de formato do gerador pode quebrá-lo.
  - **[VERIFICAR]** comportamento com o pooler real do Supabase (6543/5432); só testei em Postgres local. Funções do Drizzle (`pgTable`, `bigint({mode:'bigint'})`, `date({mode:'string'})`, `uniqueIndex`, `check`) foram conferidas pelos tipos e pela geração/execução reais.
- **Pendências e pedidos:** criptografia do `external_item_id` (E3); `.env.example` já documenta `DATABASE_URL_MIGRATIONS`? (não conferi, fora dos arquivos permitidos); CI sem Postgres: o teste de integração é pulado lá; CTO confirmar o `pnpm-workspace.yaml`.
