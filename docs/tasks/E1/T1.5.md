Valores em centavos.

## E. Gastos do período (T1.6), `domain/reports/spending.ts`

```ts
interface SpendingItem { tx: NormalizedTransaction; isTransfer: boolean }
interface SpendingSummary {
  expenses: Cents;        // compras + despesas - estornos (em módulo; pode ser negativo)
  income: Cents;
  net: Cents;             // income - expenses
  cardPayments: Cents;    // em módulo, só informativo
  investedOut: Cents;     // em módulo
  investedIn: Cents;      // em módulo
  transfers: { count: number };
  unclassified: { count: number; total: Cents };   // total com sinal
}
spendingForPeriod(items: readonly SpendingItem[], period: Period): SpendingSummary
```

Período padrão nos casos: `monthPeriod('2026-10')`. Todos os campos não citados valem 0.

| Caso | Itens (`isTransfer = false` salvo indicação) | Esperado |
|---|---|---|
| Lista vazia | `[]` | tudo 0 |
| **Compra + pagamento da fatura** | `C credit_card_purchase -10000 2026-10-01`, `S credit_card_payment -10000 2026-10-10` | `expenses 10000`, `cardPayments 10000`, `net -10000` |
| Pagamento parcial | compra `-10000`, pagamento `-5000` | `expenses 10000`, `cardPayments 5000` |
| Pagamento a maior | compra `-10000`, pagamento `-15000` | `expenses 10000`, `cardPayments 15000` |
| Estorno no mês | compra `-10000`, `refund +3000` | `expenses 7000` |
| Estorno maior que as compras | `refund +3000` sozinho | `expenses -3000` |
| **Compra em setembro, pagamento em outubro** | compra `-10000 2026-09-20`, pagamento `-10000 2026-10-10` | outubro: `expenses 0`, `cardPayments 10000`; setembro: `expenses 10000` |
| Transferência casada | `S transfer -100000`, `N transfer +100000`, ambas `isTransfer: true` | `expenses 0`, `income 0`, `transfers.count 2` |
| `isTransfer` vence o tipo | `S expense -5000 isTransfer: true` | `expenses 0`, `transfers.count 1` |
| **Caixinha** | `N investment -40000`, `N investment +40000` | `expenses 0`, `income 0`, `investedOut 40000`, `investedIn 40000` |
| Parcelado 3x | `C credit_card_purchase -3000` em `2026-10-05`, `2026-11-05`, `2026-12-05` | outubro: `expenses 3000`; novembro: `3000`; dezembro: `3000` |
| `pending` entra | `C credit_card_purchase -2500 status: 'pending' 2026-10-30` | `expenses 2500` |
| Bordas do período | linhas em `2026-09-30`, `2026-10-01`, `2026-10-31`, `2026-11-01`, cada uma `expense -100` | `expenses 200` |
| Receita | `S income +500000` | `income 500000`, `net 500000` |
| Transferência sem par | `S transfer -20000` (`isTransfer: false`) | `expenses 0`, `unclassified { count: 1, total: -20000 }` |
| `other` | `S other +700`, `S other -200` | `unclassified { count: 2, total: 500 }` |
| Mistura completa | compra `-10000`, pagamento `-10000`, estorno `+1000`, receita `+500000`, caixinha `-40000` | `expenses 9000`, `income 500000`, `net 491000`, `cardPayments 10000`, `investedOut 40000` |
| Linha inválida | `expense +100` (sinal errado) | lança `Error` |
| Sem mutação | itens e transações congelados | não lança; mesmo resultado |
| Ordem não importa | o caso "Mistura completa" invertido | mesmo resultado |

## F. Transferências internas (T1.7), `domain/transfers/`

```ts
interface TransferMatch {
  outflowIndex: number; inflowIndex: number;
  daysApart: number;                    // sempre >= 0
  confidence: 'high' | 'medium';
}
detectTransfers(txs: readonly NormalizedTransaction[], opts: { windowDays: number }): TransferMatch[]
// saída ordenada por outflowIndex
```

`windowDays: 2` salvo indicação. `T` = `type: 'transfer'`.

| Caso | Entrada (índice: conta, tipo, valor, data) | Esperado |
|---|---|---|
| Par simples | `0: S T -100000 10-06`, `1: N T +100000 10-06` | `[{0, 1, daysApart 0, high}]` |
| 1 dia de diferença | `0: S T -100000 10-06`, `1: N T +100000 10-07` | casa, `daysApart 1`, `high` |
| No limite da janela | `10-06` e `10-08` | casa, `daysApart 2`, **`medium`** |
| Fora da janela | `10-06` e `10-09` | `[]` |
| 5 dias com `windowDays: 2` | `10-06` e `10-11` | `[]` |
| Entrada antes da saída | `0: S T -100000 10-07`, `1: N T +100000 10-06` | casa, `daysApart 1` |
| **Dois pares iguais** | `0: S T -10000`, `1: S T -10000`, `2: N T +10000`, `3: N T +10000` (mesmo dia) | 2 pares; cada índice aparece uma vez só |
| Mesma conta | `0: S T -10000`, `1: S T +10000` | `[]` |
| Saída sem par | `0: S T -10000` | `[]` |
| Compra no cartão | `0: C credit_card_purchase -10000`, `1: N T +10000` | `[]` |
| `investment`, `refund` e `credit_card_payment` | cada um com um oposto `T` em outra conta | `[]` |
| Valores diferentes | `-100000` e `+99999` | `[]` |
| Zero | `0: S T 0`, `1: N T 0` | `[]` |
| `expense` com `income` | `0: S expense -10000`, `1: N income +10000` | casa, `medium` |
| **Desempate por dias** | `0: S T -10000 10-01`, `1: N T +10000 10-02`, `2: N T +10000 10-01` | `[{0, 2, daysApart 0}]`; o índice 1 fica sem par |
| Desempate por data da saída | `0: S T -10000 10-03`, `1: S T -10000 10-01`, `2: N T +10000 10-02` | `[{1, 2, daysApart 1}]` |
| **Determinismo** | o caso "Dois pares iguais" e o "Desempate por dias", embaralhados de 3 formas | os pares, convertidos para os objetos (`txs[i]`), são os mesmos em todas |
| Três contas | `0: S T -10000`, `1: N T +10000`, `2: C' T +10000` (outra conta) | um par só, com o índice 1 ou 2 conforme a regra 11 da ADR-0020 (o teste fixa qual) |
| Virada de mês | `10-31` e `11-01` | casa, `daysApart 1` |
| `windowDays` inválido (`-1`, `1.5`, `NaN`) | | lança `Error` |
| Sem mutação | entrada congelada | não lança |

## G. Categorizador (T1.8), `domain/categories/`

```ts
interface Rule { pattern: string; categoryId: string }
interface CategorizeContext {
  userRules: readonly Rule[];
  knownMerchants: readonly Rule[];
  sourceCategoryMap: ReadonlyMap<string, string>;   // categoria da fonte -> categoryId
  heuristics: readonly Rule[];
  investmentCategoryId: string;
  transferCategoryId: string;
  fallbackCategoryId: string;                       // "Outros"
}
type CategoryReason = 'type' | 'user_rule' | 'known_merchant' | 'source_category' | 'heuristic' | 'fallback';
interface CategoryResult { categoryId: string; reason: CategoryReason; pattern?: string }
categorize(input: { tx: NormalizedTransaction; sourceCategory?: string }, ctx: CategorizeContext): CategoryResult
```

Contexto dos casos: `userRules: [{ 'padaria do ze', 'cat-padaria' }]`, `knownMerchants: [{ 'uber', 'cat-transporte' }, { 'uber eats', 'cat-delivery' }, { 'padaria', 'cat-padaria-generica' }]`, `sourceCategoryMap: { 'Groceries' -> 'cat-mercado' }`, `heuristics: [{ 'posto', 'cat-combustivel' }]`, `investmentCategoryId 'cat-investimentos'`, `transferCategoryId 'cat-transferencias'`, `fallbackCategoryId 'cat-outros'`. Transação `expense -1000` salvo indicação.

| Caso | Entrada | Esperado |
|---|---|---|
| Regra do usuário vence estabelecimento | `description: 'PADARIA DO ZÉ'` | `cat-padaria`, `user_rule`, `pattern: 'padaria do ze'` |
| Estabelecimento conhecido | `'PADARIA CENTRAL'` | `cat-padaria-generica`, `known_merchant` |
| **Mais específico vence** | `'UBER EATS'` | `cat-delivery`, `pattern: 'uber eats'` |
| `UBER *TRIP` | `'UBER *TRIP'` | `cat-transporte`, `pattern: 'uber'` |
| Palavra inteira | `'UBERLANDIA COMERCIO'` | não casa `uber`; `cat-outros`, `fallback` |
| Estabelecimento vence categoria da fonte | `'UBER *TRIP'`, `sourceCategory: 'Groceries'` | `cat-transporte` |
| Categoria da fonte | `'MERCADINHO XYZ'`, `sourceCategory: 'Groceries'` | `cat-mercado`, `source_category` |
| Categoria da fonte desconhecida | `'MERCADINHO XYZ'`, `sourceCategory: 'Unknown'` | `cat-outros`, `fallback` |
| Fonte vence heurística | `'POSTO XYZ'`, `sourceCategory: 'Groceries'` | `cat-mercado` |
| Heurística | `'POSTO XYZ'` | `cat-combustivel`, `heuristic` |
| Sem correspondência | `'ABC123'` | `cat-outros`, `fallback` |
| `merchantName` também casa | `description: 'PAG*XYZ'`, `merchantName: 'Uber'` | `cat-transporte` |
| Acentos e caixa | `'Pádaria Central'` | `cat-padaria-generica` |
| **Investimento nunca é gasto** | `type: 'investment'`, `amount -40000`, `description: 'PADARIA DO ZE'` | `cat-investimentos`, `type` (a regra do usuário não vale) |
| Pagamento de fatura | `type: 'credit_card_payment'`, `'UBER'` | `cat-transferencias`, `type` |
| Transferência | `type: 'transfer'` | `cat-transferencias`, `type` |
| Empate de tamanho | `knownMerchants: [{ 'abc', 'cat-1' }, { 'xyz', 'cat-2' }]`, `'ABC XYZ'` | `cat-1` (primeiro da lista) |
| Padrão vazio ou só espaços | regra `{ '  ', 'cat-x' }` | ignorada (nunca casa) |
| Sem mutação | entrada e contexto congelados | não lança |
