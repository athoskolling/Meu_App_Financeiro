# T0.4c: Correções da T0.4r (isolamento por lista de permitidos e CI)

## Cartão (preenchido pelo CTO)

- **Estágio / tarefa:** E0 / T0.4c (correção dos achados da T0.4r, antes da T0.5)
- **Agente responsável:** dev-backend
- **Revisor:** **obrigatório** (segurança: são as travas do projeto)
- **Depende de (já em `main`):** T0.1, T0.2, T0.3, ADR-0017
- **Branch:** `agent/T0.4c-backend`

### Objetivo

Nenhum código em `domain/` consegue importar nada além de arquivos do próprio `domain/`, nem desligar o lint com comentário. O CI fica mais robusto.

### Contexto mínimo

- ADR-0017 (a decisão inteira), ADR-0016 com a emenda 1, cartões T0.2 e T0.4r. Spec 7 e 15.
- **Armadilha que o revisor achou:** a forma `regex: '^(?!\\.{1,2}(/|$)|zod$)'` do `no-restricted-imports` **falha em silêncio** para `fs`, `pg` e `@/lib/io`. Use a forma com `group`: `patterns: [{ group: ['**', '!./**', '!../**', '!.', '!..'], message: ... }]`. Confira na documentação oficial do `@typescript-eslint/no-restricted-imports` e do `no-restricted-imports` do ESLint, e cite as URLs.
- `domain/` hoje só tem `.gitkeep`.

### Arquivos permitidos

- `eslint.config.mjs`
- `tests/lint/domain-isolation.test.ts`, `tests/lint/domain-relative-imports.test.ts` (novo)
- `.github/workflows/ci.yml`
- `.gitignore`
- a seção de relatório deste cartão

Proibido: `package.json`, o lockfile, `tsconfig.json`, qualquer arquivo em `domain/` e dependências novas.

### Especificação

**1. Bloco de `domain/**` (`eslint.config.mjs`)**
- `files: ['domain/**/*.{ts,tsx,mts,cts,js,mjs,cjs}']`.
- `linterOptions: { noInlineConfig: true, reportUnusedDisableDirectives: 'error' }`.
- `@typescript-eslint/no-restricted-imports` com a lista de permitidos (só relativos, com a mensagem em português). As entradas de `paths` e `patterns` da lista de proibidos podem continuar para dar mensagens melhores. A mensagem da lista de permitidos é: "domain/ só importa arquivos do próprio domain/ (ADR-0017)."
- Para `.js`, `.mjs` e `.cjs`, se `@typescript-eslint/no-restricted-imports` não funcionar sem type-check, use a regra base `no-restricted-imports` com as mesmas opções nesses arquivos.
- Um bloco a mais para `domain/**/*.test.ts` que libera só `vitest`, além dos relativos.
- Os globais e os seletores atuais continuam (`ImportExpression`, `new Function`, `eval` etc.).

**2. JS no repositório:** um bloco `{ files: ['**/*.{js,mjs,cjs}'], ...tseslint.configs.disableTypeChecked }`, para que `.js`, `.mjs` e `.cjs` não quebrem o lint.

**3. `ignores`:** trocar `'.claude'` por `'.claude/worktrees/**'`. Se isso fizer o lint pegar arquivos de `.claude/` que quebram (ex.: `.claude/settings.json` não é JS; confira), relate e ajuste no mínimo necessário.

**4. Teste de import relativo (`tests/lint/domain-relative-imports.test.ts`)**
- Use a API do TypeScript (`typescript`, já é devDependency) para listar `domain/**/*.{ts,tsx,mts,cts}` e extrair os especificadores de import, export-from e `import x = require`.
- Para cada especificador relativo, resolver o caminho e falhar se ele cair fora de `domain/`.
- A função de checagem precisa ser testável com código em memória (sem criar arquivo em `domain/`).

**5. CI (`ci.yml`)**
- `timeout-minutes: 15` em cada job.
- `concurrency: { group: ci-${{ github.ref }}, cancel-in-progress: ${{ github.event_name == 'pull_request' }} }`.
- `persist-credentials: false` nos dois `actions/checkout`. Confira que o gitleaks continua funcionando com `fetch-depth: 0`.
- Fixar **as três actions por SHA**, com a tag num comentário (ex.: `uses: pnpm/action-setup@<sha> # v6.1.0`). Pegue os SHAs da API oficial (`gh api repos/<owner>/<repo>/git/ref/tags/<tag>`; se a tag for anotada, desreferencie até o commit) e registre no relatório como verificou. O revisor viu, no run 38751046100, `pnpm/action-setup@v6` = `0977fd99725f1db4007ccb2928dbb4e90d06cc86` e `actions/setup-node@v7` = `949feb2413d6458794dcd2491c4babbbce0c15c1`. Use isso só como conferência, não como fonte.

**6. `.gitignore`:** acrescentar `tmp/`, `.tmp/`, `exports/`, `dumps/`, `*.raw.json` e `*.private.json`.
