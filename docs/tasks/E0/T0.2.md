# T0.2 — Regra de lint que isola `domain/` de I/O

## Cartão (preenchido pelo CTO)

- **Estágio / tarefa:** E0 / T0.2 ("Regra de lint que isola `domain/` de I/O, com prova de que barra uma importação proibida")
- **Agente responsável:** dev-backend
- **Revisor:** obrigatório, na T0.4r (segurança da arquitetura: é o que garante que o núcleo financeiro não faz I/O)
- **Depende de (já em `main`):** T0.1
- **Branch:** `agent/T0.2-backend`
- **Pode rodar em paralelo com:** T0.3 (arquivos disjuntos)

### Objetivo

Qualquer arquivo em `domain/` que importe I/O, framework ou banco falha no `pnpm lint` (e portanto no CI), e há um teste permanente que prova isso.

### Contexto mínimo

- Spec 4.4, 7 e 15; `CLAUDE.md` ("`domain/` é TypeScript puro"); ADR-0016, item 6.
- O teste usa a API programática do ESLint (`new ESLint({ cwd })` + `lintText(código, { filePath: "domain/__probe__.ts" })`), então **nenhum arquivo de exemplo** é criado em `domain/`.

### Arquivos permitidos

- `eslint.config.mjs` (só o bloco aplicado a `domain/**`)
- `tests/lint/domain-isolation.test.ts`

### Regra

Bloco aplicado a `files: ["domain/**/*.ts"]`:

- `no-restricted-imports` (ou `@typescript-eslint/no-restricted-imports`) barrando:
  - qualquer módulo `node:*`;
  - módulos nativos do Node sem prefixo: `fs`, `fs/promises`, `path`, `os`, `child_process`, `http`, `https`, `net`, `crypto`, `stream`, `worker_threads`, `process`;
  - `drizzle-orm` e `drizzle-orm/*`, `pg`, `postgres`, `@supabase/*`;
  - `next` e `next/*`, `react`, `react-dom`.
- `no-restricted-globals` barrando `fetch`, `process`, `require`, `XMLHttpRequest`, `WebSocket`.
- Mensagem de erro em português: "domain/ é TypeScript puro: sem I/O, framework ou banco (ver CLAUDE.md)."
- Também barrar `import()` dinâmico desses módulos se a regra escolhida não cobrir; se não for possível, registre como risco.

### Casos de teste (escrever primeiro)

Para cada linha, `lintText` com `filePath: "domain/__probe__.ts"`:

| Código | Esperado |
|---|---|
| `import { readFileSync } from "fs";` | erro |
| `import { readFile } from "node:fs/promises";` | erro |
| `import path from "path";` | erro |
| `import { drizzle } from "drizzle-orm/postgres-js";` | erro |
| `import { createClient } from "@supabase/supabase-js";` | erro |
| `import { NextResponse } from "next/server";` | erro |
| `export const f = () => fetch("x");` | erro |
| `export const e = process.env.X;` | erro |
| `export const x = await import("node:fs");` | erro (ou risco registrado) |
| `import type { Foo } from "./foo";` | sem erro |
| `import { z } from "./local";` | sem erro |

E o controle: `import { readFileSync } from "fs";` com `filePath: "lib/__probe__.ts"` → **sem** erro de isolamento (a regra só vale para `domain/`).

### Critérios de aceite (testáveis)

- [ ] Todos os casos da tabela passam em `pnpm test`.
- [ ] `pnpm typecheck && pnpm lint && pnpm test` passam.
- [ ] Nenhum arquivo novo em `domain/`.
- [ ] `git diff --name-only origin/main...HEAD` lista só os 2 arquivos permitidos.

### Fora de escopo

Regras de estilo, regras para `lib/` ou `app/`, CI, dependências novas.

### Escalar ao CTO se

Alguma regra exigir plugin ou dependência nova (ex.: `eslint-plugin-import`); nesse caso, pare e peça.
