### Objetivo

As formas comuns de chegar em `Function` por alias deixam de passar no lint em `domain/`. O limite do lint fica documentado.

### Contexto

O QA mostrou, num clone, que estas formas em `domain/*.ts` não disparam nenhuma regra de isolamento:
- `Function.call(null, "...")()`
- `const F = Function; F("...")`
- `Reflect.construct(Function, [...])`
- `(0, Function)(...)`
- `const k = (() => 0).constructor; k(...)`

O motivo é que o seletor atual só pega `Function(...)` e `new Function(...)` diretos.

### Arquivos permitidos

- `eslint.config.mjs`: só o bloco de `domain/**`
- `tests/lint/domain-isolation.test.ts`: só acrescentar casos
- a seção de relatório deste cartão

### Especificação

1. Acrescentar `'Function'` ao `no-restricted-globals` do bloco de `domain/`, com a mensagem de domínio. O tipo `Function` já é proibido pelo `no-unsafe-function-type`.
2. Acrescentar ao `no-restricted-syntax` do bloco o seletor `MemberExpression[property.name='constructor']`, com a mensagem de domínio. Se ele quebrar algum teste atual, relate antes de mudar outra coisa.

### Casos de teste (escreva primeiro e veja falhar)

Todos em `domain/__probe__.ts`, todos com **erro**:

| Código |
|---|
| `export const a = Function.call(null, "return 1");` |
| `const F = Function; export const b = F("return 1");` |
| `export const c = Reflect.construct(Function, ["return 1"]);` |
| `export const d = (0, Function)("return 1");` |
| `const k = (() => 0).constructor; export const e = k;` |

E continua **sem erro**: `export const soma = (a: number, b: number): number => a + b;`.
