# T0.3b — Proteger a `main` e ligar a verificação de segredos do GitHub

## Cartão (preenchido pelo CTO)

- **Estágio / tarefa:** E0 / T0.3b ("Proteger `main` (PR obrigatório, CI obrigatório) e ligar as verificações de segredos do GitHub")
- **Responsável:** **o dono** (é configuração da conta no GitHub; nenhum agente tem acesso a ela)
- **Revisor:** a T0.4r confere o resultado pelas evidências desta tarefa
- **Depende de (já em `main`):** T0.3 (os jobs `check` e `gitleaks` precisam ter rodado ao menos uma vez para aparecerem na lista de verificações obrigatórias)
- **Branch:** nenhuma (só configurações em `github.com/athoskolling/Meu_App_Financeiro` → Settings)

### Objetivo

Nada entra na `main` sem PR e sem CI verde, e o GitHub bloqueia um push que contenha um segredo conhecido.

### Passo a passo (os nomes de menu são **[VERIFICAR]**: o GitHub muda a interface de vez em quando)

1. **Settings → Rules → Rulesets → New branch ruleset** (ou *Branches → Add branch protection rule*, a forma antiga):
   - Nome: `main`; alvo: branch padrão (`main`); *Enforcement*: **Active**.
   - Marcar **Restrict deletions** e **Block force pushes**.
   - Marcar **Require a pull request before merging**, com **0 aprovações obrigatórias**. Você trabalha sozinho e o GitHub não deixa o autor aprovar o próprio PR. A revisão é a cadeia QA, revisor, CTO e você.
   - Marcar **Require status checks to pass**, adicionar `check` e `gitleaks` e marcar **Require branches to be up to date before merging**.
   - *Bypass list*: deixar **vazia**. Com ela vazia, nem você consegue empurrar direto para a `main`, e é isso que queremos.
2. **Settings → Code security** (ou *Security & analysis*):
   - Ligar **Secret scanning** (gratuito em repositório público).
   - Ligar **Push protection**.
   - Opcional, recomendado: **Dependabot alerts**. Só os alertas; os PRs automáticos do Dependabot ficam fora do E0.
3. **Settings → Actions → General**: em *Workflow permissions*, deixar **Read repository contents** (só leitura).

### Critérios de aceite (testáveis)

- [ ] Um `git push origin main` direto, feito por você com um commit qualquer, é **recusado** pelo GitHub. Cole a mensagem de erro. Se o push passar, desfaça com um PR de reversão e avise o CTO.
- [ ] Um PR com CI vermelho mostra o botão de merge bloqueado (pode ser o PR de teste da T0.3 ou um descartável).
- [ ] *Secret scanning* e *Push protection* aparecem como **Enabled**. Um print da tela de configurações basta, e ele **não** vai para o repositório: mande ao CTO só o texto "ligado/desligado" de cada item.
- [ ] *Workflow permissions* em somente leitura.

### Fora de escopo

CodeQL, Dependabot com PRs automáticos, ambientes de deploy e segredos do Actions (o CI não usa nenhum).

### Escalar ao CTO se

- Os jobs `check`/`gitleaks` não aparecerem na lista de verificações. Nesse caso, provavelmente o CI ainda não rodou na `main` ou num PR.
- O GitHub exigir plano pago para algum item.
