# T0.4 — Verificação do E0 em clone limpo

## Cartão (preenchido pelo CTO)

- **Estágio / tarefa:** E0 / T0.4 ("Verificação em clone limpo: clonar, instalar e rodar os três scripts")
- **Agente responsável:** qa
- **Revisor:** vem depois, na T0.4r
- **Depende de (já em `main`):** T0.1, T0.2, T0.3 e T0.3b (proteção ligada)
- **Branch:** nenhuma. Só leitura e um clone temporário; nada é commitado.

### Objetivo

Provar que a `main` do E0, como está no GitHub, funciona para quem clona do zero e que o repositório está limpo de segredos.

### Arquivos permitidos

Nenhum no repositório. Use um diretório temporário fora do repositório e apague-o no fim.

### Roteiro

1. `git clone https://github.com/athoskolling/Meu_App_Financeiro <tmp>`, na `main`.
2. Rode `pnpm install --frozen-lockfile`, `pnpm typecheck`, `pnpm lint`, `pnpm test` e `pnpm format:check`, anotando o comando, o exit code e a saída resumida de cada um.
3. Confirme que os testes de `tests/lint/domain-isolation.test.ts` rodam e passam. Depois cole temporariamente `import fs from "fs";` num `domain/tmp.ts`, mostre que o `pnpm lint` falha com a mensagem em português e apague o arquivo.
4. `git check-ignore -v` para `.env.local`, `private/x.json`, `foo.csv`, `print.jpg` e `.claude/worktrees/x` (devem ser ignorados), e para `.env.example` e `tests/fixtures/pluggy/x.json` (não devem).
5. Se o binário do gitleaks estiver disponível, rode-o sobre o histórico do clone. Se não estiver, use o resultado do job `gitleaks` do último CI da `main` (link).
6. `git ls-files` não pode listar `node_modules`, `.env` com valor, `*.csv`, imagens fora de `docs/design/` nem nada em `private/`.
7. Confira o checklist de `docs/gates/E0.md` nas seções *Entregas*, *Qualidade* e *Segurança* e marque, para cada item, a evidência que encontrou ou "não verificado".

### Critérios de aceite (testáveis)

- [ ] Os 5 comandos passam no clone limpo.
- [ ] A violação em `domain/` é barrada pelo lint.
- [ ] O `check-ignore` dá o resultado esperado em todos os casos.
- [ ] O gitleaks não acha nada no histórico.
- [ ] Veredito PASS ou FAIL, com passos para reproduzir cada falha.

### Escalar ao CTO se

O gitleaks acusar algo. Não tente limpar o histórico.
