# T0.1 — Toolchain (pnpm, TypeScript, Vitest, ESLint, Prettier)

## Cartão (preenchido pelo CTO)

- **Estágio / tarefa:** E0 / T0.1 ("Repositório, `pnpm`, TypeScript `strict`, Vitest, ESLint, Prettier, scripts `test`/`typecheck`/`lint`")
- **Agente responsável:** dev-backend
- **Revisor:** dispensado (motivo: só configuração de ferramentas, sem regra financeira, auth, banco nem segredos; a segunda revisão de segurança do E0 acontece na T0.4r, sobre CI e lint)
- **Depende de (já em `main`):** commit inicial com `docs/`, `CLAUDE.md`, `ROADMAP.md`, `.claude/`
- **Branch:** `agent/T0.1-backend`

### Objetivo

Qualquer pessoa clona o repositório, roda `pnpm install` e tem `pnpm typecheck`, `pnpm lint`, `pnpm test` e `pnpm format:check` funcionando, com as versões da ADR-0016.

### Contexto mínimo

- Leia `docs/decisoes/0016-toolchain.md` (versões e escolhas) e a spec, seções 7 (estrutura de diretórios) e 15 (testes).
- Ainda não existe Next.js nem banco: **não** instale nada além do listado abaixo.
- A máquina do dono é Windows com `core.autocrlf=true`; por isso o `.gitattributes`.

### Arquivos permitidos

- `package.json`, `pnpm-lock.yaml` (exceção à regra de posse, autorizada por este cartão)
- `tsconfig.json`, `vitest.config.ts`, `eslint.config.mjs`, `.prettierrc.json`, `.prettierignore`, `.nvmrc`, `.gitattributes`, `.editorconfig`
- `domain/.gitkeep`, `tests/fixtures/.gitkeep`, `tests/example.test.ts`
- `.gitignore` **mínimo**, só com: `node_modules/`, `.env`, `.env.*`, `!.env.example`, `private/`, `secrets/`, `coverage/`, `dist/`. A T0.3 completa a lista.

Todo o resto é proibido (inclusive `.github/`, `.env.example` e `docs/`, que são da T0.3).

### Especificação

- `package.json`: `"private": true`, `"type": "module"`, `"packageManager": "pnpm@12.11.2"`, `"engines": { "node": ">=24" }`.
- Scripts: `typecheck` = `tsc --noEmit`; `lint` = `eslint .`; `test` = `vitest run`; `format` = `prettier --write .`; `format:check` = `prettier --check .`.
- Dependências de desenvolvimento, só estas: `typescript`, `vitest`, `eslint`, `@eslint/js`, `typescript-eslint`, `prettier`, `eslint-config-prettier`, `@types/node`. Versões estáveis atuais, fixadas pelo lockfile.
- `tsconfig.json`: `strict: true`, `noUncheckedIndexedAccess: true`, `noEmit: true`, `module`/`moduleResolution` coerentes com ESM (`"NodeNext"` ou `"Bundler"`; justifique no relatório), `target` ES2023 ou mais novo, `include` com `domain`, `tests` e os arquivos de config `.ts`.
- `eslint.config.mjs`: flat config com `@eslint/js` recommended + `typescript-eslint` recommended (type-checked, se não deixar o lint lento demais; justifique) + `eslint-config-prettier`. Ignorar `node_modules`, `coverage`, `dist`, `.next`. **Sem** a regra de isolamento de `domain/` (é da T0.2), mas deixe um bloco comentado `// T0.2: isolamento de domain/` onde ela vai entrar.
- `.prettierignore`: `pnpm-lock.yaml`, `docs/design/`, `coverage`, `dist`.
- `.gitattributes`: `* text=auto eol=lf`.
- `.nvmrc`: `24`.
- `tests/example.test.ts`: um teste trivial que passa (será substituído no E1).

### Critérios de aceite (testáveis)

- [ ] `pnpm install --frozen-lockfile` funciona num clone limpo.
- [ ] `pnpm typecheck && pnpm lint && pnpm test && pnpm format:check` passam.
- [ ] Um teste que acessa `arr[0]` sem checagem e usa o resultado como `number` **falha** no typecheck (prova de `noUncheckedIndexedAccess`). Faça esse teste localmente, descreva o resultado no relatório e **não** o commite.
- [ ] `git diff --name-only origin/main...HEAD` lista apenas arquivos permitidos.
- [ ] Nenhuma dependência além das listadas.
- [ ] `node_modules/` não aparece em `git status` nem no commit.

### Fora de escopo

Next.js, Tailwind, Zod, Drizzle, CI, `.gitignore` além do mínimo, `.env.example`, README, regra de isolamento de `domain/`, qualquer código de domínio.

### Escalar ao CTO se

- O pnpm 12.11.2 não estiver disponível ou o lockfile não se gerar.
- Alguma das ferramentas pedir dependência extra não listada.
- O lint com type-check ficar lento (mais de 30 s num repositório quase vazio).
