# T0.3 — CI, `.gitignore`, `.env.example`, CHANGELOG

## Cartão (preenchido pelo CTO)

- **Estágio / tarefa:** E0 / T0.3 ("CI (typecheck, lint, test, gitleaks), `.gitignore`, `.env.example`, pasta `docs/`")
- **Agente responsável:** dev-backend
- **Revisor:** obrigatório, na T0.4r (segurança: segredos, gitleaks, o que entra no repositório público)
- **Depende de (já em `main`):** T0.1
- **Branch:** `agent/T0.3-backend`
- **Pode rodar em paralelo com:** T0.2 (arquivos disjuntos)

### Objetivo

Todo PR para `main` roda typecheck, lint, testes e gitleaks no GitHub Actions, e o repositório (que é **público**) não aceita por engano arquivos de segredo, dados reais ou prints.

### Contexto mínimo

- Spec 14 (variáveis de ambiente, logs, backup) e 15 (CI); `docs/gates/E0.md`; ADR-0016 (Node 24, pnpm 12.11.2).
- O repositório é público: `github.com/athoskolling/Meu_App_Financeiro`.
- `docs/` já existe; não mexa no conteúdo dele, só crie `CHANGELOG.md` na raiz.

### Arquivos permitidos

- `.github/workflows/ci.yml` (exceção à regra de posse, autorizada por este cartão)
- `.gitignore`, `.env.example`, `CHANGELOG.md`
- `.gitleaks.toml` (só se precisar de allowlist; justifique cada entrada)

### Especificação

**CI (`ci.yml`)**
- Gatilhos: `pull_request` para `main` e `push` em `main`.
- `permissions: contents: read` no topo (menor privilégio).
- Job `check`: checkout, `pnpm/action-setup` (versão vinda de `packageManager`), `actions/setup-node` com Node lido de `.nvmrc` e cache do pnpm, `pnpm install --frozen-lockfile`, `pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm format:check`.
- Job `gitleaks`: checkout com `fetch-depth: 0` (histórico inteiro) e varredura com gitleaks. **[VERIFICAR]** na documentação oficial do gitleaks: versão atual da `gitleaks/gitleaks-action` e se ela exige licença para conta pessoal. Se exigir ou se houver dúvida, use o binário oficial do gitleaks (release fixada por versão) com `gitleaks git` (ou o subcomando equivalente da versão escolhida; confira). Registre no relatório o que foi verificado e onde.
- Fixe as actions por versão (tag maior no mínimo; SHA se for simples). Nenhum segredo usado no CI.

**`.gitignore`** cobre, no mínimo: `node_modules/`, `.env`, `.env.*` (com exceção `!.env.example`), `private/`, `secrets/`, `credentials.json`, `*.csv`, `*.xlsx`, `*.xls`, `*.ofx`, `*.pdf`, `*.sql`, `*.dump`, `*.png`, `*.jpg`, `*.jpeg`, `*.heic`, `*.webp`, `coverage/`, `dist/`, `.next/`, `.vercel/`, `*.log`, `.DS_Store`, `Thumbs.db`. Libere com `!` apenas `tests/fixtures/**` (fixtures fictícias) e os formatos de imagem necessários em `docs/design/` **se** houver imagens lá (hoje não há; não libere à toa).

**`.env.example`**: as 8 variáveis da spec 14, sem valores, cada uma com um comentário de uma linha: `DATABASE_URL` (pooler 6543), `DATABASE_URL_MIGRATIONS` (5432), `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `OWNER_EMAIL`, `CRON_SECRET`, `PLUGGY_CLIENT_ID`, `PLUGGY_CLIENT_SECRET`.

**`CHANGELOG.md`**: formato "Keep a Changelog", seção `[Unreleased]` e entrada `v0.0` com o que o E0 entrega (toolchain, isolamento de `domain/`, CI).

### Critérios de aceite (testáveis)

- [ ] O PR desta branch mostra os jobs `check` e `gitleaks` **verdes** no GitHub Actions (link no relatório).
- [ ] Prova do `.gitignore`: `git check-ignore -v` retorna "ignorado" para `.env.local`, `private/x.json`, `foo.csv`, `print.jpg`, `secrets/a` e "não ignorado" para `.env.example` e `tests/fixtures/pluggy/x.json`. Cole a saída no relatório.
- [ ] Prova do gitleaks: num branch **local descartável** (nunca empurrado), commite um arquivo com um segredo falso no formato de chave (ex.: um token AWS de exemplo da documentação) e rode o gitleaks localmente ou descreva como o job falharia; relate o resultado. Apague o branch depois.
- [ ] `.env.example` tem exatamente as 8 variáveis, nenhuma com valor.
- [ ] `pnpm typecheck && pnpm lint && pnpm test` passam.
- [ ] `git diff --name-only origin/main...HEAD` lista só arquivos permitidos.

### Fora de escopo

Deploy, Vercel, Dependabot, CodeQL, README, proteção da `main` (é do dono, T0.3b), mudanças no `package.json`.

### Escalar ao CTO se

- O gitleaks acusar algo no histórico atual (não tente "limpar" o histórico).
- O CI precisar de qualquer segredo ou de permissão além de `contents: read`.
- Precisar mudar `package.json` ou config da T0.1.
