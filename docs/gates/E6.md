# Gate E6 — Fechamento (v1.0)

> **Rascunho do pacote inicial.** O CTO relê e refina este checklist no início do estágio, com o que foi aprendido nos estágios anteriores, e o dono aprova. Regras gerais de gate: `docs/Meu_financeiro.md`, seção 17.

Quem fecha: o dono. Quem confere antes: o QA, o `revisor` e o CTO (diff contra este checklist).

## Entregas

- [ ] Exportação JSON e CSV corretas (contagens e valores conferem).
- [ ] **Dump restaurado num banco vazio** e as contagens conferem.
- [ ] README: um ambiente limpo sobe o projeto seguindo só o README (verificado pelo QA).
- [ ] gitleaks limpo no **histórico inteiro**; `LICENSE` presente.
- [ ] Os critérios de sucesso do MVP (spec, seção 19) percorridos um a um, com evidência.
- [ ] Backup mensal manual descrito e testado; o lembrete na interface fica para a v1.x.
- [ ] Lista da v1.x registrada (lembrete de backup, Playwright, relatórios extras, Sheets, notificações, IA).

## Para o dono explicar (sem olhar o código)

- [ ] Por que o backup fica fora do repositório e como se restaura.
- [ ] O que acontece se o Supabase Free pausar por inatividade.
- [ ] O que está de fora do v1.0 e por quê.

## Padrão (vale para todo gate)

- [ ] Todas as tarefas do estágio no `ROADMAP.md` concluídas, cada uma com QA PASS, parecer do `revisor` (quando obrigatório) e revisão do CTO.
- [ ] CI verde (typecheck, lint, testes, gitleaks); nenhum dado real, print ou dump no repositório.
- [ ] Spec e ADRs em `docs/decisoes/` atualizados.
- [ ] `CHANGELOG` com a entrada v1.0 e tag `v1.0` no Git.
- [ ] Retro curta (o que funcionou no esquema de agentes, o que mudar) e reestimativa do prazo pelo CTO.
